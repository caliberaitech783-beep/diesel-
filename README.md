# Diesel

Item Master uses one read directory across the submission store and site workspace. An item saved from either form appears in Master Data for other signed-in Master Data users, including makers and checkers routed to a different workspace. Existing saves are included without copying or approval changes. Opening a record uses its original editing workflow when permitted; otherwise it opens a read-only dialog with history and attachments. Entry still selects approved items for its assigned site.

Diesel on Azure uses verified Pulse assignments for shared Master Data. A **Master Maker** can import or enter a record and select **Save for review**. A separate **Master Checker** can approve the revision or return it with a reason. A **Master Viewer** can read and download records for the assigned site. Each edit, return, approval, deactivation and reactivation is recorded in the revision history. Entry uses the last approved revision while a change is in review.

Item Master uses a compact grid with up to five columns on desktop, section tabs, linked validation errors, an attachment preview and a comparison before saving. It has no Site input. Shared Master Data continues to enforce the assigned workspace site, and existing saved site information is retained. **Save local draft** keeps incomplete text in this browser for the current account, workspace and record; reopen the form to restore it, and reselect attachments. Other master forms retain their existing layout. Item form UI lives in `src/features/masters/item-form-page.mjs` and `assets/item-record-editor.js`.

Open a saved Diesel master by code or choose **Edit** to use a smaller dialog over the current list. **Cancel** protects unsaved edits. **Delete record** asks for a reason and confirmation. Shared records require a separate checker to approve deletion, and records used by other active masters must be unlinked first. Deleted records leave lists and pickers; their history and attachments remain. Submission owners can edit or delete their records. Company ERP records can be revised or removed from Diesel; the ERP source stays intact, and the person who saves the revision owns subsequent changes.

The **Import** and **Export** dropdowns transfer the fields for one record. Excel (`.xlsx`) and CSV use that master's field names as column headers and one data row. For PDF import, use a fillable PDF exported from that master. Review the fields and add supporting files before saving.

An Excel or CSV file with several records opens an import list on **Master Data**. Diesel reads the worksheet named after the master, or the first one, finds the header row below any title rows, and ignores columns that are not on the form. **Save for review** checks each row like the form and shows the reason beside any row it cannot save. **Open in form** carries that row into the form to correct it or add a mandatory attachment. Import up to 500 records at a time.

Diesel Rate works out the rate per kilolitre as basic rate plus excise duty, less an invoice discount, plus VAT. A post-sale discount stays out of the rate until its credit note. Use the three-line icon to return to the Master tab and the sidebar’s back arrow to open the Pulse sign-in screen.

Expand **Master Data** in the sidebar and open a master to see its saved records. The selected master hides the sidebar; use the three-line icon to return to the master list. Search beside the heading filters the records (by code or name for Diesel masters). Each table uses that master's form fields as columns. **Download** offers CSV, Excel, or PDF for every master, including the Pulse masters. Diesel masters also offer **Export**. **Import** fills one new record for review from an Excel or CSV row, a single-record Master Data PDF, or a fillable Diesel form PDF.

CMLL, Account and Location masters support multiple **Dated attributes**, each with its own optional attachment. Active approved attributes appear in the expiry list starting 30 days before their end date. Import and export carry the attribute values and dates. Reattach supporting files when importing records.

**Site**, **Region**, **Equipment**, **Employee**, **Driver** and **Shift Master** (each marked "· Pulse") lead the Master Data list and come from Pulse. The Driver Master lists everyone the ERP has recorded driving or operating a machine, with the last site, vehicle and logbook date; when Pulse cannot read the ERP it shows the directory drivers only and says so. They are read-only here: change them in Pulse. All Master Data and record lists update automatically every 30 seconds while visible, and when you return to the tab or reconnect. Pulse reads share a copy for up to 30 seconds; an outage keeps the last copy on screen and retries automatically. Search, site selection and imports stay in place; open record forms keep your edits. A login listed in `DIESEL_ALLOWED_PULSE_LOGINS` sees every site; a site Master Data role sees that site's equipment, employees and drivers. Pulse serves them from `/api/diesel-sso/masters` to Diesel's server for a signed-in person, and sends no logins, dates of birth, UAN or Aadhaar. The feature is under `src/features/pulse-masters/`.

**Storage Location Master** and **Account Master** also list the company's records from the iBoss ERP (71 storage locations and 165 accounts, supplied on 21 November 2026). Every signed-in person sees the original approved records after the saved submissions. Edit or delete them through the record dialog to save a Diesel revision; complete missing required fields before saving. They live in `src/features/company-records/` and are not checked against the form's required fields, because the ERP sheets do not carry all of them; replace the two data files to update the lists.

**Overview and checks** (first link under Master Data, `src/features/master-insights/`) gives three read-only views: record counts for every master with the Pulse fetch time and how many records still miss required fields; a site checklist showing the equipment, drivers, active shifts and storage locations each Pulse site has; and data checks for duplicates and records at sites the Site Master does not list. The sidebar shows the same counts beside each master. In any master list, the search bar can search one column and sort by any column, records with empty required fields carry an "Incomplete" mark, and on a phone each record is shown as a card.

## Run locally

**Entry → Entry workspace** opens the register for all 18 Diesel entry types. On the local preview, start with **Buy → Diesel indent**. Forms and business rules are under `src/features/entries/`.

Approve **Approval Limit Master** and **Tolerance and Alert Master** records at the site to use them in Entry. Approval records use an entry code and `All` or a slab such as `Above 200000` for E1 litres or `Above 10000000` for E2 rupees. The entry, each post and each alert are chosen from lists, so a rule names a post exactly as Pulse assigns it. Approved effective rules apply on the business date. **My alerts** routes notices in the app. A second indent while one is open needs a reason. Gate inspection can accept part of a tanker and send the rest back. A repeat override for the same vehicle within 7 days adds the Project Manager. Corrections cover any field on an entry, and a money field adds Head – Accounts. Record a post-sale discount's credit note on the posted bill. An alert is raised if the note is still due after the set days.

**My work** shows the shift, stock now and the site's entries today, with the most urgent task as the largest tile. **My approvals** lists each waiting entry with its checks and photos, to approve or return in place. On forms, lavender marks a value the system filled, amber a suggested value you changed, green a filled field and red a required field still empty. Scan a QR tag or choose an approved code. Gate entry uses the Location Master receipt scenarios and can read an invoice photo for review. Open the form while online to queue saves during a signal loss. The queue lists waiting records and syncs when the same account, site and role reconnect. Entry compresses large photos when the device supports it. Register filters apply to both CSV and Excel. Live records and downloads use the Entry role matrix and the selected site.

Approved Shift Master rows use one cut-off per site with nonoverlapping shift times. The Location Master cut-off applies before shifts are approved. Vehicle issues and daily counts can record the actual reading time in IST. Vehicle issues show the last bowser reading and compare use against approved Route Wise Diesel standards. A second repeat-fill override within seven days adds Project Manager review by default. Exception reason codes and supporting evidence follow the Reason Code Master. A Driver Master record with the operator's Login ID and a list in **Bowsers or points authorised** limits that operator's bowser loads and vehicle issues to the listed codes. UG tank to bowser suggests the bowser's **Home tank**. **My alerts** tells the Site In-charge when book stock falls below a location's **Minimum level (L)**. Bill match uses the effective Diesel Rate on the dispatch invoice date.

After E17 posts, Head – Accounts or CFO can download the balanced journal from the record. Confirm the Accounting import format and ledger codes against an actual closed month before posting it to the books.

Run `npm run preview:site-stock` and open `http://127.0.0.1:4323/entries/opening-stock`. Approve the site's observed-litre Item, Location, tanks and bowsers first. An underground tank chart uses one `cm,litres` pair per line with increasing readings through safe fill. The Site In-charge records measured balances and the Accounts-approved opening rate. The Project Manager approves the snapshot. If the rate is added later, it has its own approval and the measured balances stay locked. The separate `.local-diesel/site-entries.sqlite` ledger has all 18 Entry types. Use `DIESEL_LOCAL_MASTER_DB`, `DIESEL_LOCAL_SITE_ENTRY_DB` and `DIESEL_LOCAL_SITE_PORT` to select the master source, ledger and preview port.

Master fields that name another master are pick lists of approved records: supplier, transporter and hire party from Account Master, depot from Supplier Depot Master, the freight destination from Location Master, and an instrument's storage and a bowser's home tank from Storage Location Master. Approve the referenced record first. A saved value that is not on the list stays until someone changes it.

Site entries need approved document series for the financial year, for example `2026-27`. Purchase orders use approved supplier accounts, depot codes, and effective diesel and freight rates. Treasury records the UTR after paying through its bank. For accounts marked as subject to TDS, an approved Tax Master (TDS) row with the account's TDS Nature and Payee Category works out the deduction on payment advice and freight bills, using the yearly thresholds and the PAN dated attribute. Without a matching row, Accounts enters its approved deduction amount. Freight GST comes from the approved GST code selected on the bill. Receipts require a calibrated instrument and approved storage. Contractor recovery terms in Account Master accept `Weighted landed cost` or `Fixed rate 90000` (₹/KL). Month-end uses the approved opening rate, receipts, signed daily counts and approved clearing and consumption accounts. Check the resulting journal against the accounting system before using it for posting.

On Azure, Entry reads approved revisions from shared Master Data. A site's Location Master record starts from Pulse. When a person with a Master Data or Entry role opens **Entry workspace**, Diesel creates and approves a record for each site in their verified roles that has none, using the site name and its region as client from the Pulse Site Master copy (or the project name and client on the role), with cut-off 06:00 and both receipt scenarios. Open **Site Master** once so Diesel holds that copy. A maker can then correct the cut-off, receipt scenario and, until storage records use it, the location code; each change goes to the checker. A signed-in person with no Entry role at an approved site gets a private trial on sample sites and rates, labelled as a trial and kept apart from the live ledger. The live ledger is `/home/data/diesel-entry-review/site-stock.sqlite`. An existing installation that uses `DIESEL_SITE_MASTER_DB` continues to use that read-only approved source for Entry until its approved data is migrated to shared Master Data.

Pulse's authenticated `/api/diesel-sso/validate` response must include verified site and role pairs in `profile.dieselEntryAccess`. Entry checks each grant against the site scope or Pulse project name on an approved Location Master record. Multiple assignments appear in the site-and-role selector. **My approvals** excludes the user's own entries. A transfer's receiving site and storage can be selected once that site has approved opening stock for the same diesel item.

For Telegram approval in an HTTPS site-stock workspace, set `DIESEL_TELEGRAM_BOT_TOKEN` and `DIESEL_FAST2SMS_API_KEY` in Azure. The verified Pulse profile must provide `dieselApprovalContact` with a private Telegram `telegramChatId` string and an Indian `mobile` in +91 format, both linked to that account by Pulse. The reviewer must start a private chat with the Diesel bot. Where the approved Approval Limit Master enables Telegram, the reviewer can send themselves **Approve** and **Return** links. The link opens the selected action in Diesel. Sign in with the same Pulse account, choose the assigned site and role, and confirm via an SMS code. The proof expires after five minutes, and the entry history records the channel.

Use Node.js 24. Run `npm ci` and `npm run dev`, then open `http://127.0.0.1:3000`. `npm run preview:masters` opens the same local workspace on port 4313. The local workspace uses sample maker and checker roles and stores records in `.local-diesel/items.sqlite`. For the Location and Storage Location workflows, load the Pulse project directory with `npm run sync:pulse-projects -- "<trusted Pulse 1 checkout>"`.

To test Pulse sign-in, copy `.env.example` to `.env`, set `DIESEL_ACCESS_MODE=pulse`, and configure the issuer and shared secret. Open Diesel to enter Pulse with Diesel selected. If prompted, complete the Pulse sign-in requirements before continuing to Diesel.

Run `npm test` to check Item Master saves, local review, the form previews, and Pulse sign-in against a simulated issuer. Run `npm run build` to build `dist/`. The server starts in `src/server.mjs`. Add features under `src/features/`. Master definitions are registered in `src/features/masters/catalog.mjs`.

## Deploy

Production runs on `caliber-diesel-783` in `caliber-diesel-rg`. It shares the Central India P2v3 plan with Pulse Fleet and the HR API. Hostinger handles the DNS for `pulse-lll.cmll.in`. Azure supplies the HTTPS certificate.

1. Merge the tested change into `main`.
2. In [GitHub Actions](https://github.com/caliberaitech783-beep/diesel-/actions/workflows/azure.yml), select **Test and deploy Diesel**, choose **Run workflow** on `main`, and wait for the `deploy` job. From an authenticated GitHub CLI session, run `gh workflow run azure.yml --ref main --repo caliberaitech783-beep/diesel-`.
3. Check that the workflow verified the expected commit and `sharedMasters: ready` at the [production health endpoint](https://pulse-lll.cmll.in/healthz). With an assigned Master Maker and a separate Master Checker, verify save and approval at the same site.

If the GitHub deployment workflow is unavailable, select **Sync** in the Diesel app’s Azure Deployment Center. Confirm the expected commit in the deployment log and check that the live site responds.

Shared Master Data uses `/home/data/diesel-master-data/masters.sqlite` with rollback journaling on persistent App Service storage. Keep the SQLite-backed Diesel app on one instance. Submissions saved without a Master Data role, with their attachments, are visible to every signed-in Diesel user in **Masters** and **Master Data** (each person's own first), and a record code can be saved only once across everyone. They remain under **My earlier submissions** for makers. A maker can export a previous record and import it into the assigned site's shared workspace as a new submission for review.

The verified Pulse profile supplies `dieselMasterAccess` entries with `site` and a `role` of `maker`, `checker` or `viewer`. For Location Master, Pulse also supplies the canonical `projectName` and `client` from its project directory unless Diesel already has a synced project. For example, `{"site":"Project A","role":"maker","projectName":"Project A OC","client":"Client A"}`. Diesel derives the actor and site from these server-verified assignments. The existing `DIESEL_ALLOWED_PULSE_LOGINS` setting provides access to private submissions.

To enable Pulse sign-in, set `DIESEL_PUBLIC_ORIGIN=https://pulse-lll.cmll.in` on both apps and `PULSE_ORIGIN=https://pulse.cmll.in` on Diesel. Set the same `DIESEL_SSO_CLIENT_SECRET` on both apps, generated from 32 random bytes encoded as base64url. Fleet also needs `DIESEL_SSO_ENABLED=1`. Every signed-in Pulse user can open Diesel: a user with a Diesel site role or Entry assignment gets exactly that, and every other Pulse user gets the same access as a login listed in `DIESEL_ALLOWED_PULSE_LOGINS` (Master Data for every site, including the Pulse masters). To limit Diesel to listed logins and assigned roles again, set the Diesel app setting `DIESEL_PULSE_ACCESS=listed`; then an empty list denies all other accounts. Azure always requires Pulse. Once the Pulse issuer is ready, set `DIESEL_ACCESS_MODE=pulse` on Diesel and verify sign-in and sign-out with a Pulse account.

GitHub Actions deploys with a federated identity scoped to the Diesel Web App and trusted for `main`. It uses the `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, and `AZURE_SUBSCRIPTION_ID` secrets and the `AZURE_WEBAPP_NAME` and `DIESEL_HEALTH_ORIGIN` variables. The deployment workflow uses these repository settings from any Diesel chat.
